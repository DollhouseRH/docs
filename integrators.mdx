This page is for trading terminals, screeners and indexers that want Dollhouse launches in a new-pairs or discover feed. It covers the chain, the on-chain shape of a launch, the events that mark a round's lifecycle, the fees, and the metadata and supply endpoints. Everything below is read from the contracts and the public deployment record; nothing here requires an account or a key.

## How a launch appears on-chain

A new coin is created by `FamilyFactory.registerCandidate(name, symbol, uri, maxBond)`, which mints the token, initializes its pool and emits one event in the same transaction:

```solidity
event CandidateCreated(
    uint256 indexed roundId,
    uint256 indexed candidateId,
    address indexed token,
    PoolId poolId,
    uint160 initSqrtPriceX96,
    bool tokenIsCurrency0
);
```

`candidateId` is a global, monotonically increasing id across every round. The event does not carry the coin's name, symbol, creator or art: read those separately.

### Token metadata

Every launch is an ERC-20 clone (`FamilyToken`) with a fixed supply and no owner. Read its metadata directly off the token:

- `name()` and `symbol()` — set once at registration, never change.
- `uri()` — an off-chain metadata pointer, immutable after registration. On the current deployment this is the coin's art image URL. It is not the same as the creator-editable links described below, and it cannot be updated if a URL goes stale.
- `tokenURI()` and `metadataURI()` — the two getter names trading terminals actually look for. Both return the same value: a JSON metadata document URL built as `<metadata base>` + the token's own lowercase hex address (no checksum casing), where `<metadata base>` is a fixed prefix set once when the whole deployment was created. Fetching that URL returns:

```json
{
  "name": "Example",
  "symbol": "EXPL",
  "description": "",
  "image": "https://example.com/art.png",
  "external_url": "https://dollhouse.markets",
  "website": "https://example.com",
  "twitter": "https://x.com/example",
  "telegram": null
}
```

`name` and `symbol` are read live off the token; `image` falls back to `uri()` when no creator link has been set (and is only ever an `https:` URL); `description`, `website` and `twitter` come from the creator-editable links below when set, otherwise blank or `null`. The document is served with a public CORS header and a short cache, so a terminal can poll it freely.

The coin's creator is not in `CandidateCreated`; read `RoundManager.creatorOf(token)`, or match the token address against the `RoundManager.CandidateRegistered` event in the same block, whose `creator` field carries it directly.

### The pool

Every coin trades against exactly one other coin, its parent, in a single Uniswap v4 pool. The pool's key is:

```solidity
PoolKey({
    currency0: token < parent ? token : parent,
    currency1: token < parent ? parent : token,
    fee: 0,
    tickSpacing: 60,
    hooks: <FamilyHook address>
})
```

Currencies sort by address, ascending; `tokenIsCurrency0` in `CandidateCreated` says which side the new coin landed on. The pool id is `keccak256(abi.encode(poolKey))` — the same value already emitted as `poolId`, so it never needs to be recomputed from scratch.

**The parent currency.** While a coin is a candidate, its parent is the round's head coin: the coin at the top of the chain when the round opened (`RoundManager.RoundOpened.parentToken`, see below). If the coin wins its round and becomes a link in the chain, that same coin stays its parent permanently — a link's parent never changes after it is crowned.

**Price.** Read `sqrtPriceX96` from the pool's `slot0` (via the PoolManager or the StateView helper above, keyed by `poolId`). The raw price is `(sqrtPriceX96 / 2^96)^2`, which is currency1 per unit of currency0. To get the coin's price in its parent:

```
price_in_parent = tokenIsCurrency0 ? raw_price : 1 / raw_price
```

## Rounds

A round is a timed contest that adds the next coin to the chain. Every candidate in a round trades against the same parent, the current head coin.

<Steps>
  <Step title="Registration">
    Anyone can register a candidate by posting a bond. `RoundManager.RoundOpened` fires once, when the first candidate of a new round registers.
  </Step>
  <Step title="Trading">
    All candidate pools trade against the head coin for a fixed window.
  </Step>
  <Step title="End">
    The round's real end is settled on-chain, either from a public randomness beacon (`RoundManager.EndFulfilled`) or, if the beacon was never relayed in time, deterministically at the planned end (`RoundManager.RandomEndUnavailable`).
  </Step>
  <Step title="Finalize">
    `RoundManager.RoundFinalized(roundId, hasWinner, winnerCandidateId, ...)` names the winner, if any. The winning candidate is then written into the chain permanently via `RoundManager.HeadChanged(index, token, parent)`, which also carries the coin's numbered position in the chain.
  </Step>
</Steps>

A feed can label a coin from these three events alone:

- No `RoundFinalized` yet for its round → **candidate**, still in registration or trading.
- `RoundFinalized` fired, `hasWinner` true and `winnerCandidateId` matches → **link**, permanently in the chain (its index is in the matching `HeadChanged`).
- `RoundFinalized` fired and it did not win → **lost**, it keeps its pool and keeps trading against its parent, but it never gets a chain position.

## Opening price

Every coin's opening market cap is anchored in ETH terms and set once, at registration, on `FamilyFactory`.

```solidity
event StartPriced(
    uint256 indexed roundId,
    address indexed parent,
    uint160 sqrtP,
    uint256 D,
    uint256 A,
    uint256 B,
    uint256 flags
);
```

`sqrtP` is the reference price read from the oracle at that moment, `D` is the \$DOLL-denominated target it implies, `A` is the coin's opening market cap after the parent-relative clamp, and `B` is the curve basis passed into the sale curve. `flags` records which parts of the pricing path fired; the same value is readable later per round with `FamilyFactory.roundStartFlags(roundId)`.

| Bit | Meaning |
|---|---|
| 1 | Fallback price used |
| 2 | Young link (short price history) |
| 4 | Lower clamp applied |
| 8 | Upper clamp applied |
| 16 | Walk capped |
| 32 | Limiter engaged |
| 64 | Anchor missing |
| 128 | Stale average used |

The high byte of `flags` carries the oracle's own status at read time:

| Bit (high byte) | Meaning |
|---|---|
| 1 | No data |
| 2 | Stale |
| 4 | Fast average short |
| 8 | Slow average short |
| 16 | No read |

After one clean hour of samples (no seed and no step-limited sample in the last hour) the oracle
also prices with status 8 alone (slow average short): it uses the last hour's average, and the
24-hour average joins once it exists. Before that clean hour, and after any step-limited sample
within the last hour, a coin opens on the fallback instead.

`FamilyFactory.curveBasisOf(token)` returns the stored curve basis `B` for a launched coin; `BidDeployer` reads it to size bids so a chain-coin burn never drifts a pool's curve. `FamilyFactory.startFdvOf(token)` returns the coin's opening market cap.

`FamilyFactory.bindVenueOracle(oracle)` binds the price oracle once. It is permissionless, but only succeeds when the given address's code hash, venue pool id and pool manager all match the values fixed at deployment, so a look-alike contract can never be bound. Before it is bound, and whenever a read fails, every coin opens on the constant fallback described above, flagged in `StartPriced`.

The oracle itself exposes two read-only views:

```solidity
function startPrice() external view returns (uint160 sqrtP, uint8 status);
function latest() external view returns (uint160 stored, uint64 t, uint32 clampedStreak);
```

`startPrice()` returns the price used to anchor new coins and a status byte (0 means every average was available and fresh); `latest()` returns the most recently stored, step-limited price and how long it has been running in the same direction.

## Fees

Every Dollhouse pool takes two fees on a trade, both denominated in the coin the pool is priced in:

- **1%**, charged once per route, only on pools that sit on the edge of the chain (priced directly in \$DOLL): 40% to the coin's creator, 40% locked into buy liquidity up and down the chain, 20% to the developer.
- **0.075%**, charged on every pool regardless of position, kept by that pool as buy liquidity just under its own price.

### Trading chain coins

A chain coin trades on its canonical pool, where its fee is collected; ordinary DEX pools (v2, v3 and hookless v4) refuse it. A router should trade the canonical pool through `FamilyHook`, and settle after the swap: the hook credits the coin's canonical allowance during the swap itself, separately for each direction, so a transfer into the `PoolManager` spends only the inbound allowance and a transfer out of it only the outbound one. A router that pays the coin in before swapping finds no allowance yet and is refused. A transfer its direction's allowance does not fully cover is refused whole with `NonCanonicalVenue(from, to, reason, available)`, where `reason` is 1 for a transfer into the `PoolManager` beyond the inbound allowance, 2 for a transfer out of it beyond the outbound allowance, and 3 for a transfer to or from another pool of the coin (a contract answering `token0()` or `token1()` with the coin's address), and `available` is the allowance left in that direction (zero for reason 3). `canonicalAllowance()` returns both allowances for the current transaction. A refused `take` surfaces inside the `PoolManager`'s `WrappedError`. Nothing is charged on the coin. Wallet-to-wallet transfers, including smart wallets, are free and are not refused.

## Metadata feed

Two GET endpoints, both public and unauthenticated.

**Creator-set links and image.** `https://dollhouse-meta-api.dollhousemarkets.workers.dev/meta/4663/<token>` — the website, X account, description and image a coin's creator has set, if any. Empty JSON if none has ever been set.

```json
{
  "meta": {
    "image": "https://example.com/art.png",
    "website": "https://example.com",
    "x": { "url": "https://x.com/example", "handle": "example" }
  },
  "editor": "0x...",
  "updatedAt": 1732000000
}
```

**New-pairs feed.** `https://dollhouse-meta-api.dollhousemarkets.workers.dev/launches?chainId=4663&limit=50` — every launch, newest first, built from the on-chain events above.

```json
{
  "chainId": 4663,
  "launches": [
    {
      "candidateId": "412",
      "round": "97",
      "token": "0x...",
      "name": "Example",
      "symbol": "EXPL",
      "image": "https://example.com/art.png",
      "creator": "0x...",
      "poolId": "0x...",
      "parentToken": "0x...",
      "tokenIsCurrency0": true,
      "registeredBlock": "74350000",
      "registeredAt": 1732000000,
      "status": "candidate",
      "linkIndex": null,
      "links": { "website": "https://example.com", "x": "https://x.com/example", "telegram": null }
    }
  ]
}
```

`image` falls back to the token's own `uri()` when no creator link has been set, and is only ever an `https:` URL. `status` is one of `candidate`, `link` or `lost`; `linkIndex` is the coin's numbered chain position once it is a `link`, otherwise `null`.

## Supply

Three plain-number endpoints on the same host, for chain-listing and market-data providers:

- `GET /supply/max` — the fixed total supply.
- `GET /supply/total` — total supply minus burned tokens.
- `GET /supply/circulating` — total less burned, the launch locker, and unvested team and artist tokens.

Each responds with a bare decimal number, no JSON.
